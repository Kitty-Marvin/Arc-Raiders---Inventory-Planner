# ARC RAIDERS INVENTORY PLANNER — GitHub Pages + Firebase

**Версия 3.0, полностью браузерный доступ на нескольких ПК, без локального сервера и установки программ.**

## Что будет работать

- Произвольный инвентарь от 1 до 120 ячеек, настройка колонок.
- Поиск предметов, их изображения, категории, размер стака (если есть в каталоге).
- Перенос и перестановка предметов, изменение количества в слотах.
- До 30 сохранённых вариантов сборок, импорт/экспорт JSON.
- Синхронизация одного аккаунта между домашним и рабочим компьютером через Firebase Firestore.
- Каталог обновляется GitHub Actions два раза в неделю; если источники недоступны, старый каталог сохраняется.
- Локальное демо (без облачной синхронизации) доступно до настройки Firebase.

> **Сейчас это исходники для публикации, не уже запущенный сайт.** Для работы облака нужно выполнить следующие шаги в аккаунтах GitHub и Firebase. На ПК устанавливать ничего не требуется.

## 1. Создай бесплатный Firebase-проект

1. Открой https://console.firebase.google.com/ → **Add project / Создать проект**.
2. Оставь тариф **Spark (free)**. Опциональную Analytics можно выключить.
3. В проекте зайди в **Build / Создать → Authentication → Get started → Sign-in method → Email/Password → Enable → Save**.
4. В **Authentication → Users → Add user** вручную создай пользователя (твой email + отдельный надёжный пароль). Публичной регистрации в приложении нет.
5. В разделе **Build → Firestore Database → Create database** выбери **Standard edition** и режим Firestore (Native). Регион — удобный тебе; его потом нельзя просто поменять. Выбери **Start in production mode**, чтобы не делать данные публичными.
6. В **Firestore Database → Rules** замени правила содержимым файла `firestore.rules` и нажми **Publish**. Это обязательный шаг: без правил синхронизация не заработает.
7. В **Project overview → Project settings (шестерёнка) → Your apps → Web (значок </>)** добавь веб-приложение. Firebase выдаст конфигурацию `firebaseConfig`.
8. Открой файл `firebase-config.js` из архива и замени значения четырёх полей (`apiKey`, `authDomain`, `projectId`, `appId`) на соответствующие значения из конфигурации Firebase. Остальную структуру файла не меняй.

**Важно:** `firebaseConfig` — публичная конфигурация клиента, не администраторский ключ и не пароль. Никогда не загружай в GitHub service-account JSON, private keys или свой пароль. Доступ к сохранённым сборкам защищают Authentication + опубликованные правила Firestore.

## 2. Создай бесплатный GitHub Pages

1. Открой https://github.com/ и авторизуйся. Нажми **New repository**.
2. Имя, например, `arc-inventory-planner`, ветка по умолчанию **main**, видимость **Public**. На GitHub Free Pages работает с публичными репозиториями.
3. В репозитории **Add file → Upload files** и загрузи **содержимое распакованной папки**, а не ZIP: `index.html`, `app.js`, `firebase-config.js`, `firestore.rules`, `README.md`, `catalog/`, `scripts/` и `.github/workflows/deploy.yml` (последний файл обязательный). Если при загрузке через браузер вложенная `.github` не загрузилась, создай её файл через **Add file → Create new file**, указав путь `.github/workflows/deploy.yml`, и вставь текст из архива.
4. Перейди в **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Перейди в **Actions → Publish ARC Planner and refresh item catalog → Run workflow** (если первое обновление уже было запущено до включения Pages, перезапусти). Дождись зелёной отметки обеих задач `build` и `deploy`.
6. В **Settings → Pages** появится адрес вида **`https://ТВОЙ-ЛОГИН.github.io/arc-inventory-planner/`**. Любой ПК открывает его без установки софта.
7. В Firebase перейди **Authentication → Settings → Authorized domains → Add domain** и добавь **`ТВОЙ-ЛОГИН.github.io`** (без `https://` и без пути).
8. Открой сайт, введи email и пароль пользователя из шага 1. Сборки будут храниться в Firebase и доступны на обоих ПК после входа в один аккаунт.

**Если GitHub показывает 404:** проверь имя главной ветки `main`, наличие `.github/workflows/deploy.yml`, Source = GitHub Actions и статус рабочего процесса в Actions. На сайте при первом запуске каталог может отображать только 8 демонстрационных предметов, пока первый успешный запуск обновления не получит данные из MetaForge или ARDB.

## 3. Как обновляются предметы

- При первом запуске GitHub Actions пытается загрузить предметы, изображения и категории из **MetaForge**, а также **ARDB** как дополнительный источник.
- Автоматически запускается по понедельникам и четвергам (UTC). Можно обновить раньше: **Actions → Publish ARC Planner and refresh item catalog → Run workflow**.
- Источники могут менять API или выдавать ошибки. При недоступности показывается прежняя версия каталога или небольшой демо-каталог. Изображения загружаются с серверов источников и могут временно не отображаться.
- Кнопка **«Обновить»** в каталоге перечитывает уже опубликованный JSON. Для загрузки новых игровых предметов запусти workflow на GitHub.

Источники: https://metaforge.app/arc-raiders/api, https://metaforge.app/arc-raiders и https://ardb.app/developers/api. Использование некоммерческое, с указанием авторства данных. Игра не подключается к этому приложению.

## 4. Важные ограничения

- Синхронизация происходит **только после входа**. Локальное демо сохраняется отдельно в браузере и **не** синхронизируется.
- При первом входе, если облако пусто, приложение предложит перенести локальные данные.
- Если изменения внесены на двух ПК одновременно, действует защита от перезаписи; экспортируй конфликтующий вариант в JSON, затем нажми «Обновить».
- Для удобства **Экспорт всех сборок** делает резервную копию. Firestore не заменяет бэкапы.
- Файлы сайта публикуются публично, а сборки хранятся отдельно в Firestore и приватны благодаря правилам Firebase. Не помещай личную информацию в исходники.
- Бесплатный Spark и GitHub Pages доступны **при соблюдении лимитов**. При превышении бесплатных лимитов сервис может приостанавливать операции до следующего расчётного периода; платный тариф не включается автоматически.
- API-поля (изображения, категории, стаки) могут со временем меняться. Если автоматическое обновление не удалось, сначала проверь **Actions → build → лог**.

## Структура

- `index.html` — интерфейс
- `app.js` — интерактивность и Firebase Auth/Firestore
- `firebase-config.js` — публичные параметры твоего Firebase-проекта (заполнить)
- `firestore.rules` — закрытые правила базы (опубликовать вручную в Firebase)
- `catalog/metaforge.json`, `catalog/ardb.json` — кеш каталогов, первоначально пустой
- `scripts/update_catalog.py` — обновление на GitHub Actions, без Python на твоём ПК
- `.github/workflows/deploy.yml` — одновременное обновление каталога и публикация сайта
- `.nojekyll` — для статической публикации
