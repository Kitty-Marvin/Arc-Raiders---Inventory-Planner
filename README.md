# ARC RAIDERS STASH & LOADOUT PLANNER — v5.0

**Два отдельных раздела:**

- **Склад / STASH (главный раздел):** план виртуального хранилища в ангаре Сперанцы. Стартовая ёмкость — **64 ячейки**, быстрые варианты 64/88/112/.../328 и ручное значение до 600 ячеек (для дополнительных бонусов). Один стак занимает одну ячейку.
- **Сборки для рейда / LOADOUTS:** отдельное пространство для подготовки снаряжения перед выходом. Старт 24 условные ячейки, вручную до 120 (упрощённая модель, **не автоматическая копия реальных слотов аугмента**).

В обоих разделах: каталог предметов и изображения от MetaForge/ARDB (кэш обновляется GitHub Actions), настройка количества, перемещение мышкой, сохранённые варианты, публикация выбранного варианта друзьям, просмотр опубликованного плана без входа, копирование плана, облачная синхронизация через Firebase (после настройки), демонстрационный режим без регистрации, экспорт и импорт JSON.

Это **ручной планировщик**: он не подключается к игре и не считывает автоматически ваш настоящий Stash.

## Обновление существующего проекта GitHub (с v3 или v4)

В репозитории `Kitty-Marvin/Arc-Raiders---Inventory-Planner` замените файлы:

- `index.html`
- `app.js`
- `firestore.rules`
- `README.md`

Оставьте папки `catalog`, `scripts`, `.github` и `firebase-config.js` без изменений. **Не заменяйте настроенный `firebase-config.js`**, если уже вставили Firebase API config.

В GitHub: **Add file → Upload files**, перетащите эти четыре файла, затем **Commit changes**. Если GitHub Pages настроен на GitHub Actions, публикация запускается через **Actions → Publish ARC Planner and refresh item catalog → Run workflow** (проверить название в `.github/workflows/deploy.yml`).

## ОБЯЗАТЕЛЬНО: обновите правила Firestore в консоли Firebase

GitHub Pages хранит код сайта, но **не управляет правилами Firebase**.

В https://console.firebase.google.com/ откройте ваш проект → **Firestore Database → Rules**. Замените содержимое на текст **нового** `firestore.rules` из этого архива и нажмите **Publish**. Иначе облачный раздел «Склад» и опубликованные планы большого размера не смогут сохраняться.

Кроме того:

1. **Authentication → Sign-in method → Email/Password → Enable** для входа и регистрации через сайт.
2. **Authentication → Settings → Authorized domains**: `kitty-marvin.github.io` (без `https://`).
3. **Firestore Database**: создайте базу **Standard / Native mode** с режимом Production, если она ещё не создана.
4. **Project settings → Your apps → Web**: создайте веб-приложение и скопируйте значения `firebaseConfig` в `firebase-config.js` на GitHub.
5. В GitHub **Settings → Pages → Source = GitHub Actions**; затем откройте вкладку Actions, дождитесь успешного развертывания.

Адрес страницы будет вида:

`https://kitty-marvin.github.io/Arc-Raiders---Inventory-Planner/`

## Сохранность данных при переходе с v4

- **Старые облачные инвентари и сборки v3/v4 остаются в разделе «Сборки для рейда»** (`users/{uid}/planner/main`).
- **Новый склад** хранится отдельно (`users/{uid}/planner/stash`).
- Локальные демо-сборки прежней версии доступны в рейдовом разделе (сохраняются старые ключи браузера); новый склад имеет отдельные ключи.
- При обмене по ссылке теперь сохраняется тип плана: склад или рейд. **Старые ссылки v4** автоматически открываются как рейдовые.
- Смена вкладок не должна сбрасывать сохранённые данные; при несохранённых изменениях в облаке переключение блокируется.
- Сохранённые варианты одного раздела экспортируются отдельным JSON. Не стирайте старые резервные копии.
- Публичной становится **только явно опубликованная копия плана**, а не весь склад. Для этого нужны правильные Firestore Rules.

## Ограничения

- До 30 сохранённых планов на каждый раздел. Слишком большой набор может упереться в лимит документа Firestore 1 МиБ; приложение проверяет размер перед сохранением.
- Вкладка рейда — пока упрощённая сетка; реальные ячейки экипировки (оружие, броня, карманы, аугменты и вес) можно добавить следующим этапом.
- Количество на экране планировщика не списывается автоматически со склада при создании рейдовой сборки.
- Изменения между устройствами требуют интернет-соединения и входа в один аккаунт Firebase. Демо хранится только в конкретном браузере.
- Обновление каталога зависит от доступности сторонних источников. Если недоступны, показываются старые данные или ограниченный демо-каталог.
- В этой поставке правила Firestore необходимо опубликовать вручную; без подключения настоящего проекта Firebase облачная работа не проверена.

Кредит источников: MetaForge (`https://metaforge.app/arc-raiders`), ARDB (`https://ardb.app`). Неофициальный инструмент, не связанный с Embark Studios.
